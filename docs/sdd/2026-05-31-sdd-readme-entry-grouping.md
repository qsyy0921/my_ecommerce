# SDD README 入口分组治理

## 背景

前几轮审计已经确认 `docs/sdd` 存在两个文档治理问题：

- 审计文档碎片化。
- 剩余问题优先级拉平。

`README.md` 原先主要是一个完整历史索引。它保留了所有 SDD 文档入口，但随着文档数量增加，阅读者很难快速判断应该先看哪几篇。

本轮不重写历史文档，不合并旧文档，只在 `README.md` 增加主题入口。

## 本轮改动

在 `docs/sdd/README.md` 中新增 `主题入口`，按以下分组组织阅读顺序：

- 现态与任务。
- 交易主链路。
- 基础设施边界。
- 业务完备度。
- 测试守护。
- 文档与面试口径。

同时保留 `完整历史索引`，避免丢失早期 SDD 记录。

## 设计理由

这种方式比直接重排或合并所有历史索引更稳：

- 历史索引仍然完整。
- 新读者可以先看主题入口。
- 后续新增文档可以先进入某个主题组，再决定是否需要加入完整历史索引。
- 不需要大规模改动旧文档引用。

## 验收

- `README.md` 增加主题分组入口。
- `README.md` 保留完整历史索引。
- `tasks.md`、`ddd-sdd-todo-list.md`、当前风险地图同步记录。
- 本轮不修改生产代码。

## 后续要求

后续新增 SDD 文档时，需要先判断属于哪个主题：

- 交易主链路。
- 基础设施边界。
- 业务完备度。
- 测试守护。
- 文档与面试口径。

如果无法归类，优先考虑是否真的需要新增文档，而不是继续追加碎片化审计。
